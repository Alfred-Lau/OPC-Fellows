# OPC-Fellows Agent 工作台 — 从模块视图到会话工作区

> 目标：把现在「左侧 rail + 中间一张模块视图」的工作台，改造成参考产品那种 **左栏身份 / 中栏会话 / 右栏工具与工作文件** 的 Agent 工作区。
> 关键翻转：**内置模块不再是侧栏上的一个页面，而是新建 Agent 时的职业模板**；用户启用或「新建」一个模块，本质是创建一个 Agent 实例。当前所有 Agent（内置默认实例 + 用户自建）都进入推荐列表。
>
> 本文叠在 [module-architecture-design.md](./module-architecture-design.md) 之上：Cordis 内核、模块契约、capability、仓库与隔离 **全部保留**。本轮改的是外壳心智与一等公民实体，不是再做一遍模块化。

本文只做布局拆解、实体关系与系统设计，不含实现代码。

---

## 0. 与既有设计的关系

模块化文档已经把「功能硬编码」拆成了 **内核服务 + Cordis 插件 + manifest**。那一层回答的是「代码怎么插拔」。

本设计回答的是另一层问题：

| 问题 | 模块化文档 | 本文 |
|---|---|---|
| 一个功能在进程里是什么 | Cordis 插件 + 存储命名空间 | 不变 |
| 用户眼里一个功能是什么 | 侧栏导航上的一个视图 | **一个可 @ 的 Agent**，带工作目录与工具面板 |
| 用户怎么「加上」一个功能 | 设置里 enable 模块 | **新建 Agent**：选模板或空白创建 |
| 用户同时在干什么 | 停在某一个 `view-*` | 开着一个会话；会话里可以 @ 多个 Agent；右侧是当前上下文的文件与工具 |
| Agent 这个词现在指什么 | 待办 `origin: 'agent'` + `agentId` 字符串 | 一等公民：身份、模板、工作区、能力、参与会话 |

一句话：**模块是能力包（代码），Agent 是能力包的一次具身（身份 + 工作目录 + 配置），会话是工作发生的地方。**

## 1. 参考产品布局拆解

截图是一个典型的「对话驱动的多 Agent 工作室」，不是传统后台的「模块切换器」。三栏各自承担不同时间尺度的对象。

```
┌──────────────┬─────────────────────────────┬──────────────────────────┐
│  左栏 · 身份  │  中栏 · 会话                   │  右栏 · 工作区            │
│  选「和谁、   │  当前这件事怎么推进            │  这件事用到的文件与工具   │
│  哪件事」     │                             │                          │
│              │                             │                          │
│  全局动作     │  会话标题 + 参与者             │  工具页签（文件 / 面板）  │
│  最近会话     │  多 Agent 消息流               │  目录树 / 模块原生 UI    │
│  AGENTS 列表  │  @提及、技能引用               │  与当前会话或 Agent 绑定  │
│  项目列表     │  输入框（技能 / 本机 / 发送）   │                          │
└──────────────┴─────────────────────────────┴──────────────────────────┘
```

### 1.1 左栏：选上下文，不选「页面」

从上到下四层，层次不能混：

| 层 | 截图里的东西 | 时间尺度 | 选中后发生什么 |
|---|---|---|---|
| **全局动作** | 新任务、日程、扩展、云盘 | 跨会话 | 打开内核能力，不绑定某一个 Agent |
| **最近会话** | 「示例项目」、首页 | 一件正在做的事 | 中栏切到该会话消息流，右栏切到该会话工作区 |
| **AGENTS** | 内容编辑、科研助理、Mina… | 一个身份 | 打开与该 Agent 的默认会话，或进入其主页 |
| **项目** | 小程序、新项目、演示项目 | 一组会话 + 文件的容器 | 过滤左栏会话，右栏切到项目根目录 |

底部是账号与设置，与 rail 里的模块开关不是一类东西。

关键观察：**左栏没有「收款管理」「项目监控」这种功能页入口。** 那些能力被收进了 Agent 身份里。用户先选人或选事，再在中栏说话、在右栏看产物。

### 1.2 中栏：会话是唯一的工作主轴

中栏不是某个模块的 DOM，而是一条 **Thread**：

- 标题是这件事的名字（「示例项目」），不是模块名。
- 参与者可以是多个 Agent（标题旁 `2`、气泡里的 `@通用助手` `@内容编辑`）。
- 消息是异构的：人说话、Agent 回复、系统转发（「这份素材在哪个文件夹」被系统转给两个成员）。
- 输入框是 **技能入口 + 本机上下文 + 发送**，不是「拆成待办」的单行表单。`/` 引用技能，本机标识（`opc.local`）声明工具跑在哪台机器。

这对 OPC-Fellows 的含义：首页那句「先写一句 → 拆成待办」要升级成「先开一件事 → @ 该出场的 Agent」。待办仍然是内核，但是会话的一种产出，不再是唯一的交互面。

### 1.3 右栏：当前上下文的工具与文件

「工作文件」不是全局网盘的缩略图，而是 **当前会话绑定的工作区快照**：

- 目录树按这件事组织（`assets` / `drafts` / `plan` / `library`）。
- 文件类型混杂：图片、PDF、Markdown、JSON —— Agent 的中间产物和最终交付都落在这里。
- 顶栏是文件搜索、刷新、以及可切换的工具页签（文件 / 其他面板）。

对 OPC-Fellows 的含义：今天每个模块自己占满中栏的图表、列表、表单，迁移后变成该 Agent 的 **工具面板**，默认停在右栏。会话在中间问「这个月收款如何」，右侧打开收款台账；会话问「明日 OPC 待办」，右侧打开监控态势。

### 1.4 新建 Agent 对话框：模板先于空白

第二张图把「创建」拆成两条路：

```
┌─────────────┬──────────────────────────────────────────┐
│ 直接创建     │  空白 Agent：自己填名称 / 工作目录 /      │
│              │  描述 / 扩展能力（插件、技能、MCP）        │
├─────────────┤                                          │
│ 模板创建     │  职业模板列表：视频导演、编程专家、         │
│ 视频导演     │  自媒体运营达人、调研分析师、投资顾问…     │
│ 编程专家     │  选中后预填名称、工作目录、能力包          │
│ …            │                                          │
└─────────────┴──────────────────────────────────────────┘
表单：Agent 名称 * · 工作目录名称 · 描述 · 扩展能力
```

三条对 OPC-Fellows 直接可用的规则：

1. **空白创建永远在。** 不选模板也能拥有一个通用 Agent（对应现在的 Harness / 首页拆解）。
2. **模板 = 预装好的能力包 + 默认工作目录约定 + 一段人设。** 不是另一套代码分发渠道。
3. **扩展能力是创建时勾选的，不是写死在模板里不能改的。** 模板给推荐集，用户可加减插件 / 技能 / MCP。

## 2. 业务实体与关系

从布局反推，真正稳定的对象只有六个。模块、视图、导航项都是这些对象的投影。

```
                    ┌──────────────┐
                    │   Project    │  一组会话与文件的容器（可选）
                    └──────┬───────┘
                           │ 1:n
                           ▼
┌────────────┐  参与 n:n   ┌──────────────┐  绑定 1:1   ┌─────────────┐
│   Agent    │────────────│    Thread    │────────────│  Workspace  │
│  身份实例   │            │    会话      │            │  工作区      │
└─────┬──────┘            └──────┬───────┘            └──────┬──────┘
      │ 实例化                    │ 1:n                      │ 含
      ▼                          ▼                          ▼
┌────────────┐            ┌──────────────┐            ┌─────────────┐
│  Template  │            │   Message    │            │  Artifact   │
│  职业模板   │            │ 人 / Agent / │            │ 文件、面板、 │
│ = 模块投影  │            │ 系统转发      │            │ 待办、通知   │
└─────┬──────┘            └──────────────┘            └─────────────┘
      │ 由……提供
      ▼
┌────────────┐     扩展      ┌────────────┐
│   Module   │─────────────│ Capability │
│  Cordis 能力包 │           │ 插件/技能/  │
│  （已有）    │             │ MCP/工具   │
└────────────┘             └────────────┘
```

### 2.1 实体定义

**Module（已有，保持）**
Cordis 插件 + manifest。提供代码、IPC、存储命名空间、capability、可选的原生 UI。它 **不知道** 自己在会话里叫什么、工作目录在哪。内置十个模块继续是能力包，第三方模块继续走仓库安装。

**AgentTemplate（新，职业模板）**
给用户看的「创建时选什么」。一条模板引用 1 个或多个 Module，带默认人设、默认工作目录规则、推荐能力集、是否允许复用（单例 / 多实例）。内置模块每份都有一条对应模板；也允许组合模板（例如「自媒体运营达人」= `accounts` + `social-ammo` + `x-push`）。

**Agent（新，身份实例）**
用户真正 @ 的对象。字段最小集：

| 字段 | 含义 |
|---|---|
| `id` | 稳定身份，同时是待办 `agentId`（取代今天散落的 `MONITOR_AGENT_ID` 等常量） |
| `templateId` | 来自哪条模板；空白创建则为 `blank` |
| `title` / `mark` / `description` | 展示名、单字印、工作重点 |
| `workspace` | 工作目录（见 Workspace） |
| `moduleIds` | 实际启用的能力包，创建后可改 |
| `capabilities` | 额外挂上的技能 / MCP / 插件 |
| `kind` | `conversational` / `dashboard` / `window` / `background` |
| `singleton` | 该模板是否只允许一个实例（收款、监控默认是） |
| `origin` | `builtin-default` / `user` / `cloned` |

启用一个内置模块 = 确保该模板的 **默认 Agent** 存在。用户再「新建」= 再实例化（多实例模板）或打开已有单例并允许改名改人设。

**Thread（新，会话）**
一件正在做的事。绑定：标题、参与 Agent 列表、消息、工作区、可选所属 Project。首页「今日态势」不再是一个特殊 view，而是一个 **系统会话**（收件箱 + 今日提醒 + 未完成待办），固定不可删。

**Workspace（新，工作区）**
一个目录 + 一组工具面板。目录可以是 `userData/workspaces/<agentOrThreadId>/`，也可以指向用户本机文件夹（对齐截图里的「云盘 / Rumi」）。工具面板来自绑定 Agent 的 Module UI：监控的图表、收款的台账、选品的 idea 流，都是面板，不再是独占中栏的 view。

**Project（轻量，可后做）**
会话与工作区的分组。现有 `monitor` 里的代码项目、SaaS 站点，先作为监控 Agent 工作区内的对象，不必第一期提升为全局 Project。左栏「项目」分组有了再升级。

**Message / Artifact**
消息可 @ Agent、引用技能、附带产物指针。Artifact 包括：工作区文件、经 `ctx.todos.ingest` 写下的待办、桌面通知、模块面板的一次刷新结果。待办继续是内核对象，只是多了一条 `threadId` 可选外键。

### 2.2 关系约束

1. **Module 1 — n Template。** 多数是 1:1（`payments` →「财务顾问」）。组合模板是 n:1 的反方向：一条模板挂多个模块。
2. **Template 1 — n Agent。** 单例模板在数据层仍是 1:1，UI 上「再新建」会提示「已有实例，打开或改名」。
3. **Agent n — n Thread。** 一条会话可以 @ 多个 Agent（截图正是这样）；一个 Agent 可以出现在多条会话里。
4. **Thread 1 — 1 Workspace。** 会话的文件树以会话工作区为准；若会话尚未自建目录，则回落到 **主对话 Agent 的工作区**。
5. **Agent 1 — 1 默认 Workspace。** 创建时必填「工作目录名称」，即使暂时是空目录。
6. **跨 Agent 写待办必须带 `agentId = Agent.id`。** 今天模块直写常量 id，迁移后走实例 id，收件箱去重逻辑不变。
7. **禁用 Module ≠ 删除 Agent。** 能力包停掉后，Agent 仍在左栏，状态为 `needs-module`，会话里 @ 它会提示「能力已停用」。数据与工作区保留。这与模块化文档「禁用不丢数据」一致。

### 2.3 和今天对象的对照

| 今天 | 改造后 |
|---|---|
| `WorkbenchView` / `NavEntry` | 不再是主导航。左栏导航变成 Thread + Agent + 全局动作 |
| `ModuleInfo` + `workbench.yml` entry | 仍是能力包的启停配置 |
| `BUILTIN_MODULES` | 同时生成 `BUILTIN_TEMPLATES` |
| `todos.ingest({ agentId: 'monitor' })` | `ingest({ agentId: agent.id })`，默认实例 id 可保持 `'monitor'` 以兼容旧待办 |
| `view-home` 今日态势 | 系统 Thread `thread:inbox` |
| `view-todos` | 内核工具面板，也可从全局动作「新任务 / 日程」打开 |
| `view-settings` | 全局动作 / 账号区进入，不属于 Agent |
| `view-payments` 等模块页 | 对应 Agent 的右栏默认面板 |
| `kind: 'window'`（pet） | Agent.kind = `window`，点击仍开独立窗口，但左栏出现在 AGENTS |
| `kind: 'background'`（x-push） | Agent.kind = `background`，左栏可隐藏，作为别的模板的扩展能力出现 |
| DeepSeek Harness 孤岛窗口 | 空白模板 / 通用助手的运行时；中栏会话默认走它 |
| 设置里的模块开关 | 仍保留，作为「能力包总闸」；日常入口改为新建 / 停用 Agent |

## 3. 当前项目卡在哪

模块化已经让「代码可拔」，外壳还停在 **功能页切换器**：

```
aside.rail          →  每个启用模块一个按钮
div.stage
  section#view-*    →  同一时刻只亮一个模块的整页 UI
```

症状：

- **Agent 有 id 没有身份。** `monitor` / `micro-sourcing` / `payments` 三个字符串只用来打待办来源，左栏看不到它们，也不能 @，更不能配工作目录。
- **模块 = 页面。** 收款和监控无法同时「在场」：要么看台账，要么看态势。参考产品里它们可以同时被一条会话 @ 到。
- **没有工作区。** 公众号草稿的 Markdown、选品的 idea、社媒弹药的文案，各自躺在自己的 json 里，用户不能在一个文件树里看到「这件事的产物」。
- **创建路径是开关不是诞生。** 设置里 enable `micro` 和「我新雇了一个选品策略师」不是同一件事。后者需要名字、工作目录、人设、可选的额外 MCP。
- **Harness 是孤岛。** 真正能对话的运行时开在另一扇窗 / 中栏 iframe，工作台中栏自己又做了一套 `ctx.llm.complete`。参考产品的中栏就是运行时。根因与改判见 [ADR 0005](./adr/0005-dsh-as-composition-host.md)。
- **推荐无从挂靠。** 没有 Agent 实例表，就无法把「当前所有 Agent」当成下一张新建表单的推荐。

这些不是模块化文档的漏洞，是文档有意先做的「完整形态模块仓库」还没碰到外壳心智。现在补这一层，正好赶在第三方模块 API 定型之前（模块化文档 §16：先让内置模块经过真实检验再开放仓库）。

## 4. 目标心智模型

用户打开工作台时，脑子里是三句话：

1. **我现在在做哪件事？** → 选或新建一条 Thread（中栏）。
2. **这件事该叫谁？** → @ 已有 Agent，或新建一个（从模板 / 从推荐 / 空白）。
3. **产物在哪？** → 右栏工作区。问句留在中栏，表和文件留在右栏。

开发者脑子里仍是模块化文档的那句：

4. **能力从哪来？** → Module 继续 `apply(ctx)`，启停、capability、仓库、隔离都不动。

因此有两条创建路径，必须分开，不能再混在设置页一个开关里：

| 路径 | 谁用 | 结果 |
|---|---|---|
| **新建 Agent** | 日常 | 一个可 @ 的身份 + 默认会话 + 工作目录；若模板依赖的模块未启用，顺手 enable |
| **启用 / 停用模块** | 设置 / 开发者 | 能力包在进程里上电或断电；已有 Agent 变为可用或 `needs-module` |

内置模块「新建的时候提供选择」落在第一条路径的左栏模板列表里，而不是设置页。

## 5. 三栏外壳

把现在的 `aside.rail + div.stage` 扩成三栏。内核壳永远在；中栏与右栏可按会话折叠右栏（窄屏默认收起，与现在 rail 折叠同一套记忆键）。

### 5.1 左栏结构

```
[品牌]  [搜索 ⌘K]

全局动作
  新任务      → 打开/聚焦系统收件会话，光标进输入框
  日程        → 右栏切到待办面板（按 notifyAt）
  扩展        → 设置·模块与仓库（能力包总闸）
  云盘        → 右栏切到全局工作区根（所有 Agent 目录的索引）

会话
  今日        → 系统 Thread（原首页）
  …用户会话   → 按更新时间

AGENTS
  [+] 新建 Agent
  …Agent 列表（默认实例 + 用户自建）
  停用的能力包对应 Agent 打角标，不消失

项目          ← 第二期；第一期可只显示监控 Agent 内的项目快捷方式

────────────
账号 · 主题 · 设置
```

模块不再往 `ctx.workbench.nav()` 贡献「主舞台页面」。改为：

- 模板 / 默认 Agent 由内核在模块 `ACTIVE` 时登记到 `ctx.agents`
- `kind: 'window'` 的 Agent 点击仍走现在的 `open()`（台伴独立窗）
- `kind: 'background'` 默认不进 AGENTS 主列表，出现在「扩展能力」和组合模板里

### 5.2 中栏：会话运行时

系统收件会话保留今日态势的信息密度（提醒、未完成、标签），但输入框语义从「拆成待办」扩展为：

- 不 @ 任何人：行为与现在相同，走 `ctx.todos` 拆解。
- `@收款管理 这个月 MRR`：消息进会话，派给该 Agent；右栏若未打开收款面板则打开。
- `/技能`：引用某 Agent 声明过的技能或模块工具。
- 本机标识：第一期固定为本机 Electron；对话后端是 dsh SDK session，不再显示 sidecar origin。

非系统会话的中栏就是消息流。模块的重型 UI **不**在中栏重绘一遍。

### 5.3 右栏：工作区宿主

右栏是一个 **面板槽**，不是第二个 stage：

| 页签 | 来源 |
|---|---|
| 文件 | 当前 Workspace 的目录树（第一期可先做 `userData/workspaces` 的只读树 + 打开外部文件夹） |
| 工具 | 当前聚焦 Agent 的 Module UI（把现有 `view-payments` 等整页迁进来，样式改为嵌入列宽） |
| 待办 | 过滤到本会话 / 本 Agent 的 `agentId` |

没有聚焦 Agent 时（系统收件会话），右栏默认待办面板。用户点 AGENTS 里某个身份，右栏切到它的默认工具页签。

现有 `index.html` 里写死的 `section#view-*` 迁入右栏宿主：`#workspace-stage`。内核待办 / 设置仍可全幅打开（全局动作），避免把设置塞进 320px 列。

### 5.4 响应与折叠

- 默认：左 220 / 中自适应 / 右 360（可拖）。
- 收起右栏：变回今天的两栏，工具面板改成中栏覆盖层，避免「改了布局却没屏显示表」。
- 收起左栏：与现在 rail 折叠相同。

## 6. 新建 Agent 流

对齐截图对话框，字段与数据落到第 2 节的实体上。

### 6.1 左列：直接创建 / 模板 / 推荐

```
直接创建
  空白 Agent          templateId = 'blank'，运行时 = Harness / ctx.llm

模板创建（内置模块投影，新建时必给选择）
  项目监控官           monitor
  选品策略师           micro
  财务顾问             payments
  自媒体运营达人       accounts + social-ammo + x-push
  公众号编辑           wxdraft
  随手记               notes
  社媒弹药手           social-ammo（单独一条，给只做内容的人）
  台伴                 pet（window）
  DeepSeek 工作台      harness（已退出花名册；运行时是 SDK）

推荐 Agent（当前所有已存在的 Agent）
  把 list() 出来的实例按最近使用排。点一项 =「以它为蓝本再创建一个」
  （复制人设、能力集、工作目录规则，不复制会话与数据文件）
  单例模板的推荐项改为「打开已有的「收款管理」」而不是再克隆一份账本
```

「当前所有 Agent 都可以作为推荐」是硬规则：用户自建的「Rumi」、克隆出来的第二个选品助手、内置默认实例，全部进入推荐区。推荐不是另一份静态清单。

### 6.2 右列表单

| 字段 | 必填 | 默认 |
|---|---|---|
| Agent 名称 | 是 | 模板 title；空白则「换一个」随机名 |
| 工作目录名称 | 否 | `云盘 / <名称>` → `userData/workspaces/<slug>/`；允许改成本机绝对路径 |
| 描述 | 否 | 模板 description，限 100 字（对齐截图） |
| 扩展能力 | 否 | 模板推荐的 moduleIds + 已装 MCP/技能；`+` 打开能力选择器 |

提交时：

1. 校验名称、id 不冲突。
2. 模板依赖的 Module 若 disabled → 先 `ctx.modules.enable`（失败则 Agent 建成 `needs-module`）。
3. 写 Agent 记录，建 Workspace 目录。
4. 若 `kind` 需要默认会话，创建 Thread「与 <名称> 的对话」，参与者 = [该 Agent]。
5. 左栏 AGENTS 出现新项，中栏切到默认会话，右栏打开其工具面板（无 UI 的 background/window 则只开文件树或独立窗）。

### 6.3 内置默认实例

为了不让老用户打开软件后 AGENTS 是空的：每个已 enable 的内置模块在启动时 **幂等** 确保一条 `origin: 'builtin-default'` 的 Agent，`id` 等于今天的模块 id（`monitor` / `payments` / …），这样旧待办上的 `agentId` 不用迁。

用户可以改默认实例的显示名（「项目监控」→「OPC 监工」），不能换它的 `id`，不能删掉只能停用模块。

## 7. 内置模板目录

每条模板都是 Module 的投影，不是第二份实现。`kind` 决定它在三栏里怎么出现。

| 模板 id | 标题 | 引用模块 | Agent.kind | 单例 | 右栏默认面板 | 中栏能对话吗 |
|---|---|---|---|---|---|---|
| `blank` | 直接创建 | （无，用 ctx.llm / harness） | conversational | 否 | 文件 | 是 |
| `monitor` | 项目监控官 | monitor | dashboard | 是 | 监控整页 | 经工具：刷新、问态势 |
| `micro` | 选品策略师 | micro | dashboard | 否 | 选品流 | 经工具：扫描、盯 idea |
| `payments` | 财务顾问 | payments | dashboard | 是 | 收款台账 | 经工具：同步、问 MRR |
| `creator` | 自媒体运营达人 | accounts, social-ammo, x-push | dashboard | 否 | 账号 + 弹药 | 经工具：写弹药、发 X |
| `wxdraft` | 公众号编辑 | wxdraft | dashboard | 否 | 草稿工作台 | 经工具：转稿、上传 |
| `notes` | 随手记 | notes | conversational | 是 | 笔记列表 | 是：记下即写笔记 |
| `social-ammo` | 社媒弹药手 | social-ammo | dashboard | 是 | 弹药（从监控页剥离后） | 经工具 |
| `pet` | 台伴 | pet | window | 是 | —（独立窗） | 否，通知入口 |
| `harness` | DeepSeek 工作台 | harness | window（花名册隐藏） | 是 | — | 是，运行时本体；不进可雇列表 |
| `x-push` | X 推送通道 | x-push | background | 是 | 不进主列表 | 作为扩展能力 |

「经工具」的意思：第一期不要求每个 dashboard Agent 都能自由闲聊。中栏 @ 它时，内核把自然语言路由到该模块已有的 bridge action（`sync` / `refresh` / `state`），用固定回复 + 打开右栏。真正的多轮对话留给 `blank` / `harness` / 声明了 `tools` 的模块（模块化文档 §11，原 P6）。

组合模板 `creator` 是唯一需要在 manifest 之外多写一份 Template 记录的地方：三个模块仍可单独 enable，但新建时给用户一条「职业」而不是三个开关。

## 8. 内核服务增量

不替换 `ctx.modules` / `ctx.workbench`，只加三件事。判断标准仍是模块化文档那句：拿掉它工作台就不再是工作台。

| 服务 | `ctx` 键 | 职责 |
|---|---|---|
| Agent 注册表 | `ctx.agents` | 模板表、实例 CRUD、默认实例幂等、推荐列表、`needs-module` 状态 |
| 会话 | `ctx.threads` | Thread CRUD、消息追加、参与者、@ 派发、系统收件会话 |
| 工作区 | `ctx.workspaces` | 目录约定、列出文件、打开外部路径、把 Module UI 贡献成右栏面板 |

`ctx.workbench` 的职责收缩为：**窗口、托盘、快捷键、三栏壳的打开/聚焦**。不再把模块 id 当成 view id。`showWorkbench('payments')` 这类调用改为 `ctx.workbench.focusAgent('payments')`（切右栏面板 + 如无会话则打开默认会话）。

`ctx.todos.ingest` 增加可选 `threadId`；`agentId` 必须是已登记 Agent。未知 id 仍然写入（兼容旧数据），但设置页打「无主待办」。

IPC 继续走泛化桥：

```
workbench.invoke('agents', 'list' | 'create' | 'recommend' | …)
workbench.invoke('threads', 'list' | 'append' | …)
workbench.invoke('workspaces', 'tree' | 'open' | …)
```

preload 不用为 Agent 再开命名空间。

### 8.1 推荐接口

`ctx.agents.recommend(query?: string)` 返回两段，供新建对话框一次拉齐：

```ts
{
  templates: AgentTemplate[]   // 内置 + 组合，按 group
  agents: Agent[]              // 当前全部实例，最近使用优先；含 builtin-default
}
```

没有第三段「运营推荐位」。推荐 = 现在机器上真实存在的 Agent。卸载模块导致默认实例进入 `needs-module` 时，推荐里仍在，标注「能力已停用」。

## 9. 模块契约要补的字段

现有 `ModuleManifest` 够跑启停，不够投影成模板。内置模块的 `manifest.ts` 增加可选段，缺省由内核推断：

```ts
template?: {
  /** 新建对话框里的职业名，缺省用 title。 */
  role: string
  /** conversational | dashboard | window | background，缺省从 kind 映射。 */
  agentKind?: AgentKind
  /** 缺省：view/window 为 true，background 为 true。 */
  singleton?: boolean
  /** 人设 / 工作重点，新建表单描述的默认值。 */
  persona?: string
  /** 默认工作目录名，相对云盘根。缺省为 title。 */
  workspaceName?: string
  /** 出现在「扩展能力」里的推荐项（技能名 / MCP / 其他 module id）。 */
  suggestedCapabilities?: string[]
}
```

组合模板不写进某个模块的 manifest，写在内核的 `BUILTIN_TEMPLATES` 里，避免三个模块互相 inject 出环。

模块继续 `ctx.workbench.nav(...)` 可以暂时保留作兼容，内核同时把它登记成默认 Agent。P3 迁完外壳后，nav 贡献改为 `ctx.agents.contributeFromModule(manifest)`，导航项从 Agent 列表派生。

## 10. 存储布局

在模块化文档 §12 的 `userData/` 上追加，不改模块数据位置（收款仍在 `module-data/payments/`，避免账本跟着某个 Agent 克隆而复制）。

```
userData/
  kernel/
    todos.json
    agents.json          ← 模板缓存不必持久化（内置+组合是代码）；只存实例
    threads.json         ← 会话与消息（消息量大时按 thread 分文件）
    theme.json
  workspaces/
    inbox/               ← 系统收件会话
    monitor/             ← 默认实例工作区（可空，文件型产物才往这写）
    payments/
    <user-slug>/
  module-data/           ← 不变：能力包的权威数据
  …
```

原则：**权威业务数据留在模块命名空间；工作区只放会话产物与用户拖进去的文件。** 克隆 Agent 不复制 `module-data`。单例模板共享同一份 `module-data`；多实例且需要隔离数据的模板（选品、公众号、空白）在实例 config 里带自己的 storage key，由模块在 `apply` 时读取 —— 第一期只给 `blank` / `wxdraft` / `micro` 开这个口，其余单例共享。

现有待办 `agentId: 'monitor'` 与默认实例 id 对齐，**零迁移**。`micro-sourcing` 这个历史 id 在默认实例上继续用，模板 id 仍是 `micro`，用 `agent.id` 而不是 `template.id` 去 ingest。

## 11. 会话如何调用模块（第一期要克制）

完整的「Agent 调用模块工具」是模块化文档 P6（dsh 双向融合）。本轮外壳如果等 P6，三栏会变成空壳。折中：

**第一期路由（规则，不跑大模型也成立）**

1. 消息未 @ → 系统收件会话：现有拆解。
2. 消息 @ 了 dashboard Agent → 打开其右栏面板；若文本匹配已有 action 关键词（「刷新」「同步」）则 `invoke` 该 action，把结果摘要写回一条系统消息。
3. 消息 @ 了 conversational Agent（blank / notes）→ 交给 `dshRuntime.prompt`，允许它 `todos.ingest` 和读写该 Agent 工作区。
4. 多 @ → 生成一条系统转发消息（把问题转给两个成员），再按 2/3 各派一次。不在第一期做 Agent 之间的自动辩论。

**第二期** 才把模块 `tools` 注册进 dsh，让空白 Agent 真正「查一下这个月收款」。那是 P6，不挡三栏上线。

## 13. 迁移路径

仍然「每一阶段可跑、可发版」，接在模块化 P0–P2 已经落地的内核之后。编号用 A，避免和模块化 P 混。

**A0 · 实体与默认实例（无 UI）**
`ctx.agents`：模板表、实例持久化、启动时为每个 ACTIVE 内置模块 upsert 默认 Agent。待办 ingest 校验改走注册表。设置页模块卡片加一行「对应 Agent：项目监控官」。这一阶段用户感知为零，但 `agentId` 从此有主。

**A1 · 新建对话框**
设置页或 rail 底加「新建 Agent」。实现 §6 的直接创建 / 模板 / 推荐。创建空白 Agent 只登记身份 + 空工作区，还没有三栏。推荐列表的数据源必须是 `ctx.agents.recommend()`，从第一天就包含全部实例。

**A2 · 三栏壳**
`index.html` / `app.css` / `app.ts` 改为左会话与 Agent、中消息、右宿主。系统收件会话承接今日态势。模块 section 先 **原样搬进右栏**（窄列下能滚即可），不重做 payments/monitor 的信息架构。左栏不再列出模块 view。窗口类 Agent 点击行为保持。

**A3 · 会话消息与 @**
中栏可发消息、可 @ Agent、可按 §11 第一期规则路由。多 @ 只做系统转发。输入框 `/` 先只列出该会话参与者声明的 bridge action 名，不做技能市场。

**A4 · 工作区文件树**
右栏「文件」页签读 `userData/workspaces`。公众号草稿、选品导出、弹药文案若已是文件则链进来；json 库不复制。支持把工作目录指到本机文件夹（只列、用 shell 打开，第一期不做编辑器）。

**A5 · 组合模板与推荐打磨**
加上 `creator` 组合模板；推荐区按最近会话加权；单例模板在推荐里显示「打开已有」而不是「再来一个账本」。

**A6 · 与 [ADR 0005](./adr/0005-dsh-as-composition-host.md) 汇合（原模块化 P6）**
不再把模块 tools 桥进 sidecar。中栏会话就是 dsh session；记下 / 刷新态势 / 同步收款 / 选品扫描挂在 `ctx.tools`。口令仍走 bridge，说不清的话让模型点名工具。

约束：

- A2 之前不要删 rail 模块入口（A0/A1 双轨：旧导航仍在）。
- A2 当天必须能从左栏点到每个原模块的右栏面板，否则这是一次视觉降级。
- 不在本轮重做 monitor / payments 内部页面。
- 不在本轮把 todos 改成可禁用模块（模块化 §5.1 仍然成立：待办是内核，是系统会话的骨架）。

| 风险 | 说明 | 对策 |
|---|---|---|

## 15. 决策记录

### 已定

1. **模块继续是能力包，不是页面，也不是 Agent。** Agent 是模板的一次具身。新建内置能力的用户路径是「新建 Agent」，设置里的模块开关降为总闸。
2. **每个内置模块（及一条组合模板）在新建对话框里必须能被选到。** 这是「内置模块新建时提供选择」的字面落地。
3. **`ctx.agents.recommend()` 返回当前全部 Agent 实例。** 没有静态运营位；用户自建的与默认实例同等资格。
4. **启用内置模块时幂等创建默认 Agent，id 对齐今天的 ingest `agentId`。** 旧待办零迁移。
5. **外壳改成左身份 / 中会话 / 右工作区。** 模块原生 UI 进右栏；系统收件会话承接首页。
6. **第一期会话路由用规则，不把职业自动协作提前。** 对话后端本身按 ADR 0005 收进 dsh，不再用自制 `ctx.llm` 顶一程。多 @ 仍只转发。
7. **权威业务数据留在 `module-data/`。** 工作区只放产物与用户文件。
8. **待办仍是内核。** 系统会话 + 全局「新任务 / 日程」是它的入口，不是一个可删 Agent。
9. **window / background 模块可以是 Agent，但不强行塞进右栏。** pet 保持独立窗；x-push 作为扩展能力。`harness` 不再当可雇职业，见 ADR 0005。

### 明确不做（本轮）

- 不做扣子式云端多用户、积分、职业模板市场。
- 不做真实云盘同步；「云盘」是本地工作区根的名字。
- 不把第三方模块仓库改成 Agent 商店；仓库仍卖能力包，安装后出现在新建表单的扩展能力里。
- 不在本轮实现 Agent 之间的自动多轮协作。
- 不重写 payments / monitor 信息架构。

### 待定（实现 A2 时再拍板，不挡 A0）

- 右栏默认宽度、是否允许把工具面板「钉」到中栏全幅。
- 系统收件会话要不要保留今日态势的三列卡片，还是全部改到右栏待办页签。
- ~~`harness` 是否在 A3 就嵌入中栏~~ 已定：不嵌入官方 UI，中栏走 dsh session（ADR 0005）。

## 16. 验收标准（用来判断「改造完成」而不是「做完扣子」）

1. 冷启动后，每个已启用内置模块都能在 AGENTS 里看到对应默认实例，且旧待办的 `agentId` 仍能对上。
