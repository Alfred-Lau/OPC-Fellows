# Workbench Skill 先赋能再调用

职业 SOP 仍按 [0001](./0001-occupation-skills.md) 私有。技能页上的投资 / OPC / 网站 / 合作设计 / 产品设计是另一层：用户点选后弹出成员名单，写入该成员的 `skillIds`。只有被赋能的成员在主对话（implicit）和项目（主成员或 `@`）里会 invoke 这条 Skill。

调用与保存走现有线程，不另开技能仓库：

1. **赋能**：`agents.json` 里该成员的 `skillIds`。撤下即删。
2. **听见**：仍按 [0002](./0002-skill-route-matching.md) —— 主对话不必 @，项目没 @ 只有主成员，今日必须 @。
3. **分配**：有 key 时把职业 Skill 和已赋能 Skill 一起交给模型；无 key 时用口令 / Trigger 兜底。
4. **执行**：能对上职业 SOP 的零歧义写口令走原 invoke；读句、模糊句和建议类走该成员 `chat`（人设含 Skill 合同与工具，不再另开 skillChat 入口）。
5. **保存**：用户句已在 `post` 时写入 `threads.json`；成员回复经 `reply` 落同一条线程。建议没有第二份 Artifact。

## 考虑过但没选

- 点卡片就 `@` 默认职业：赋能关系不持久，项目里别人听不见。
- 技能可挂任意身份并改写职业 SOP：和 0001 打架。赋能只加建议层，不替换职业目录。
- 建议结果另存技能档案：和「线程即记录」重复，跨成员也难对齐主人。
